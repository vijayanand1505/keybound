# KEYBOUND design review and implementation plan

Reviewed 28 October 2026 against all 31 sections and appendices of `../../KEYBOUND-Game-Design-Document.md`. The original document is preserved unchanged. The v0.2 [motion update](ANIMATION-UPDATE.md) adds distinct animated side-mode worlds and expands the scene-feedback implementation described below.

## Product conclusion

The strongest differentiator is the connection between typing and a world that reacts. The story gives practice a purpose; the coast, mountain, terminal, sound, and consequences need to reinforce that purpose. A themed typing test alone will not deliver the full vision.

The current build is a playable prototype, not the complete MVP described in the document. It establishes a guest-first game loop with two expedition scenes, five additional mode environments, 16 original missions, feedback, daily practice, and local persistence. It has no account requirement, advertising, purchases, or external analytics. Low Orbit now includes a separate real-time Signal Siege arcade; three future story expeditions remain marked as in development.

Attracting users and improving typing are hypotheses to test. Neither the GDD's 10–20% improvement goal nor its retention targets should be advertised as established results. Competitor descriptions in the GDD are positioning assumptions rather than a current market audit.

## Design ambiguities resolved for this prototype

1. **Home row versus narrative.** Full English messages cannot be restricted to `ASDF JKL;`. The home-row mission is a dedicated drill, validated against those characters. Narrative missions advertise letters and spaces. White Ascent reinforces top-row use rather than claiming exclusive top-row content.
2. **Standard error correction.** A wrong character stays at the same cursor. The next correct character clears it. Backspace first clears a current mistake; otherwise it moves back one committed character. All recorded errors remain in accuracy. This reconciles the GDD's stop-on-letter example with its error table.
3. **WPM.** `net/useful WPM = current committed character count / 5 / active minutes`. `gross WPM = printable attempts / 5 / active minutes`. `accuracy = correct printable attempts / all printable attempts × 100`. Backspace/control keys are not printable attempts. A minimum one-second denominator avoids enormous first-frame figures. Wrong attempts and retyping cannot inflate useful WPM. The GDD's gross-minus-uncorrected-errors formula does not define corrected attempts clearly enough for this mode.
4. **Consistency and Flow.** These currently use coefficient of variation of the most recent 24 valid correct-key intervals (0–3,000 ms), excluding pause boundaries. This is a rolling rhythm measure, not whole-session per-second WPM consistency. Flow ramps as samples accumulate and drops on errors. It is feedback, not yet a timed power-up.
5. **Daily fairness.** Text is derived from a versioned seed and UTC date, giving the same route on clients with correct clocks and the same build. This is an unranked practice route. A server must define canonical time, text version, and allowed attempts before competitive use. No paid cron or database is needed to generate this prototype route.
6. **Ranks.** Prototype titles depend only on local XP. They do not represent server-verified skill or complete the GDD's rank requirements.
7. **Mission duration.** Briefings show a time window. Actual play may be shorter for fast typists; Calm has no time pressure. The current text lengths do not promise a two-minute minimum.
8. **Rewards.** Replays can earn local XP and do not affect competition. No reward economy or cosmetic store exists yet.

## Architecture and upgrade path

- `app/`: server entry, metadata, global styles, locally hosted fonts.
- `components/Keybound.tsx`: menu and mission lifecycle, accessible input surface, debrief and settings. Split into route/screen components as the next milestone adds services; current screen selection is local state, not deep-link routes.
- `components/Scene.tsx`: code-native vector coast and mountain scenes. Keeps original art editable without image-generation dependencies.
- `game/typing.ts`: input/session state, monotonic timing, metrics, deterministic seeded word selection and coach scoring.
- `game/storage.ts`: versioned IndexedDB records; bounded history and export/delete.
- `game/audio.ts`: gesture-activated Web Audio feedback.
- `content/missions.json`: original briefings, original typing passages, objective data and reward configuration.

Next backend step: Supabase Auth + Postgres with RLS, then a server-owned run protocol. Do not store service-role keys in client code. Persist verified runs in Postgres before introducing a second leaderboard store; add Redis only when measured read volume justifies it. Signed seeds and replay recomputation need rate limiting, expiry, and a replay version. Synthetic-event blocking is only input hygiene and can be bypassed by a modified client.

## Milestones and acceptance gates

### A. Playtest this prototype

- [x] Complete guest journey, local data, daily route, trial, practice, result sharing.
- [x] Original coast/mountain environments and 16 scripted missions.
- [ ] Five people play without instructions; observe first key, first error, completion, repeat intent, readability, discomfort.
- [ ] Profile input latency and frame time on an integrated-GPU laptop/Chromebook.
- [ ] Compare useful WPM and accuracy on identical replay fixtures with the chosen external benchmark.

### B. Deliver distinct game mechanics

- [ ] Mission segment schema with words/passage/burst/choice and validated transitions.
- [ ] Precision error budgets and persistent in-world recovery consequences.
- [ ] Coast three-ship boss with independent deadlines; mountain avalanche chase and actual route choice.
- [ ] Per-bigram coaching, keyboard layout packs, classified errors, finger guidance.
- [ ] Score stars, first-clear bonuses, collectible letters and story-based progression.
- [ ] Typed choices and reactive dialogue rather than only narration.

### C. Trusted public MVP

- [ ] Auth, optional guest merge and cross-device sync.
- [ ] Signed session issuance, canonical UTC daily, server replay recomputation, abuse limits, pending verification and moderation.
- [ ] Global daily board, async challenge URLs and ghosts, dynamic OG cards.
- [ ] Privacy/terms, deletion/export for server data, callsign moderation and name clearance.
- [ ] End-to-end CI against preview deployments; input/IME/layout matrix and accessibility audit.
- [ ] Real media/performance budgets, feature flags, privacy-respecting measurement and operating budget alerts.

### D. Expand after evidence

Expeditions 3–6, code languages, community packs, seasons, live races, co-op, classrooms, offline/PWA and 3D scenes. Each should earn its place based on playtests and operating cost. Multiplayer and classrooms are separate service projects, not additions to the current terminal UI.
